# AI新闻洞察 · 网站前端

网站名称：**AI新闻洞察**  
副标题：**收藏价值新闻，提炼洞见**

## 页面结构（2026-11-01 确认版）
1. 顶部仅保留名称和副标题。
2. 直接展示「精选文章」，按照 AI 洞察日报的「AI市场动态 / 产品与运营洞察」大类及子类排列。
3. 「全部 / 个人收藏 / 日报点赞」筛选在精选文章顶部，无独立冗余内容层。
4. 页脚仅保留 AI 洞察日报与 GitHub 知识库两处原始资料入口。

文章包含标题、原始摘要、来源标签、日期、原文链接；只有明确记录用户个人感想才展示「我的感想」。不能将“点赞了”或“待补充”推断为个人判断。

## 数据
- 主数据：`data/articles.json`，由本仓库 GitHub 原始文件 URL 提供。
- 回退：同目录 `website/articles.json` 快照。
- 前端会按原文链接去重，并合并同一篇文章的多种来源标签。
- 现有 13 篇作为初始快照，未将其声称为实时同步结果。
- 若启用前端远程读取，部署域名需允许请求 GitHub raw；网络失败时页面读取本地快照。

### 自动同步尚需后端数据写入
当前静态网页**不能自行访问用户私有的日报点赞、ChatGPT 收藏记录或定时任务执行记录**。要形成真正端到端自动更新，需要：
1. 从日报站点获得经过授权的点赞事件数据（文章 ID、原文 URL、日期、时间、用户）。
2. 从收藏工作流获得收藏事件或导入操作（文章 ID、原文 URL、日期、摘要、个人感想）。
3. 通过受保护的服务端同步任务去重、分类和更新 `data/articles.json`，并同步 `website/articles.json` 快照。
4. 测试新增点赞/收藏、取消动作、重复原文、同步失败与刷新后的显示一致性。

没有这两个数据源的 API 或写入链路时，**不要**把数据抓取、浏览器端轮询或静态页面加载称为“自动同步成功”。

## 部署边界
这个目录是 GitHub 存档的前端副本。已存在的 `ai-frontier-library-luoqing.wulizhenmin.chatgpt.site` 由 ChatGPT Sites 托管，并非 GitHub Pages；修改 GitHub 文件不会自动覆盖那个站点。需要在 Sites 项目中导入/修改前端并重新发布，且按用户原要求先获得发布许可。
